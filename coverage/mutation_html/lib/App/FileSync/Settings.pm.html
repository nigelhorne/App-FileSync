  456: =head1 NAME
  457: 
  458: App::FileSync::Settings - process-wide settings and logging for App::FileSync
  459: 
  460: =head1 SYNOPSIS
  461: 
  462:     use App::FileSync::Settings;
  463: 
  464:     my $logger = App::FileSync::Settings::logger(verbose => 1);
  465:     $logger->error('...');
  466: 
  467:     my $settings = App::FileSync::Settings::load();
  468:     my $level = $settings->{log_level};
  469: 
  470:     my $report = App::FileSync::Settings::explain();
  471:     printf "%s = %s (%s)\n", $_->{key}, $_->{value}, $_->{label}
  472:         for @{ $report->{settings} };
  473: 
  474: =head1 DESCRIPTION
  475: 
  476: Settings that apply to the process rather than to one repo - the log level,
  477: format and destination, plus the SSH identity, known-hosts file and remote
  478: server command - are read through L<Object::Configure>.  The repos themselves
  479: remain in F<~/.filesync/config.json>, which C<filesync init> writes; this
  480: module does not replace that store.
  481: 
  482: The settings file is F<~/.conf/app-filesync.json> when it exists, or the path in
  483: C<FILESYNC_SETTINGS>.  The section key is C<App__FileSync>, and a C<UNIVERSAL>
  484: section in the same directory applies to every class that uses
  485: Object::Configure.  Environment variables named C<App__FileSync__I<key>>
  486: override the file:
  487: 
  488:     # ~/.conf/app-filesync.json
  489:     { "App__FileSync": { "log_level": "debug", "log_format": "%level%: %message%" } }
  490: 
  491:     # or
  492:     export App__FileSync__log_level=debug
  493: 
  494: C<log_file> sends the log to a file instead of standard error; leading
  495: directories are created.  C<log_format> is a L<Log::Abstraction> format string.
  496: 
  497: C<ssh_identity>, C<ssh_known_hosts> and C<server_command> are the defaults for
  498: every SSH repo, so a per-repo C<identity>, C<known_hosts> or C<server_command>
  499: (written by C<filesync init --identity> and friends) only has to be set when it
  500: differs.  C<server_command> defaults to C<filesync-server>:
  501: 
  502:     { "App__FileSync": {
  503:         "ssh_identity"    : "~/.ssh/filesync_ed25519",
  504:         "ssh_known_hosts" : "~/.ssh/filesync_known_hosts",
  505:         "server_command"  : "/usr/local/bin/filesync-server"
  506:     } }
  507: 
  508: Command output (sync summaries, plans, C<--json>) is written to standard output
  509: by the commands themselves; the logger carries diagnostics on standard error,
  510: so a cron job can separate the two.  C<--verbose> raises the level to C<debug>
  511: and C<--quiet> lowers it to C<error> for that run, overriding the file.
  512: 
  513: =head1 FUNCTIONS
  514: 
  515: =head2 logger
  516: 
  517:     my $logger = App::FileSync::Settings::logger(%args);
  518: 
  519: Returns a L<Log::Abstraction> writing to standard error (or C<log_file>).
  520: C<config_file>, C<config_dirs>, C<level>, C<verbose> and C<quiet> may be passed.
  521: 
  522: =head2 load
  523: 
  524: Returns the merged settings hashref (without the Object::Configure logger).
  525: 
  526: =head2 config_file
  527: 
  528: Returns the settings file that would be used, or C<undef>.
  529: 
  530: =head2 explain
  531: 
  532:     my $report = App::FileSync::Settings::explain(%args);
  533: 
  534: Returns C<{ settings_file =E<gt> $path_or_undef, settings =E<gt> \@rows }>, with
  535: one row per key in C<@App::FileSync::Settings::SETTING_KEYS>.  Each row has the
  536: effective C<value>, a C<source> of C<default>, C<file>, C<env> or C<merged>, anda human-readable C<label> naming the file section, environment variable or
  537: built-in default that supplied it.  C<config_file> and C<config_dirs> may be
  538: passed, as for C<load>.
  539: 
  540: =head2 explain_repos
  541: 
  542:     my $repos = App::FileSync::Settings::explain_repos(%args);
  543: 
  544: Resolves C<ssh_identity>, C<ssh_known_hosts> and C<server_command> for every
  545: repo in a client config.  C<config> is the hashref from
  546: C<App::FileSync::Config::load_client>, C<report> is the result of C<explain>,
  547: and C<config_file> is the client config path used in labels.
  548: 
  549: Each entry has C<repo>, C<transport>, C<server> (when the repo records one) and
  550: C<ssh>: one C<{key, value, source, label}> row per setting, where C<source> is
  551: C<repo> (the repo's own entry), C<process> (the settings reported by C<explain>)
  552: or C<default> (ssh's own default, when nothing sets a value).  C<ssh> is
  553: C<undef> for the local transport, which never runs ssh.
  554:
