  425: =head1 SYNOPSIS
  426: 
  427:     use App::FileSync::Settings;
  428: 
  429:     my $logger = App::FileSync::Settings::logger(verbose => 1);
  430:     $logger->error('...');
  431: 
  432:     my $settings = App::FileSync::Settings::load();
  433:     my $level = $settings->{log_level};
  434: 
  435:     my $report = App::FileSync::Settings::explain();
  436:     printf "%s = %s (%s)\n", $_->{key}, $_->{value}, $_->{label}
  437:         for @{ $report->{settings} };
  438: 
  439: =head1 DESCRIPTION
  440: 
  441: Settings that apply to the process rather than to one repo - the log level,
  442: format and destination, plus the SSH identity, known-hosts file and remote
  443: server command - are read through L<Object::Configure>.  The repos themselves
  444: remain in F<~/.filesync/config.json>, which C<filesync init> writes; this
  445: module does not replace that store.
  446: 
  447: The settings file is F<~/.conf/app-filesync.json> when it exists, or the path in
  448: C<FILESYNC_SETTINGS>.  The section key is C<App__FileSync>, and a C<UNIVERSAL>
  449: section in the same directory applies to every class that uses
  450: Object::Configure.  Environment variables named C<App__FileSync__I<key>>
  451: override the file:
  452: 
  453:     # ~/.conf/app-filesync.json
  454:     { "App__FileSync": { "log_level": "debug", "log_format": "%level%: %message%" } }
  455: 
  456:     # or
  457:     export App__FileSync__log_level=debug
  458: 
  459: C<log_file> sends the log to a file instead of standard error; leading
  460: directories are created.  C<log_format> is a L<Log::Abstraction> format string.
  461: 
  462: C<ssh_identity>, C<ssh_known_hosts> and C<server_command> are the defaults for
  463: every SSH repo, so a per-repo C<identity>, C<known_hosts> or C<server_command>
  464: (written by C<filesync init --identity> and friends) only has to be set when it
  465: differs.  C<server_command> defaults to C<filesync-server>:
  466: 
  467:     { "App__FileSync": {
  468:         "ssh_identity"    : "~/.ssh/filesync_ed25519",
  469:         "ssh_known_hosts" : "~/.ssh/filesync_known_hosts",
  470:         "server_command"  : "/usr/local/bin/filesync-server"
  471:     } }
  472: 
  473: Command output (sync summaries, plans, C<--json>) is written to standard output
  474: by the commands themselves; the logger carries diagnostics on standard error,
  475: so a cron job can separate the two.  C<--verbose> raises the level to C<debug>
  476: and C<--quiet> lowers it to C<error> for that run, overriding the file.
  477: 
  478: =head1 FUNCTIONS
  479: 
  480: =head2 logger
  481: 
  482:     my $logger = App::FileSync::Settings::logger(%args);
  483: 
  484: Returns a L<Log::Abstraction> writing to standard error (or C<log_file>).
  485: C<config_file>, C<config_dirs>, C<level>, C<verbose> and C<quiet> may be passed.
  486: 
  487: =head2 load
  488: 
  489: Returns the merged settings hashref (without the Object::Configure logger).
  490: 
  491: =head2 config_file
  492: 
  493: Returns the settings file that would be used, or C<undef>.
  494: 
  495: =head2 explain
  496: 
  497:     my $report = App::FileSync::Settings::explain(%args);
  498: 
  499: Returns C<{ settings_file =E<gt> $path_or_undef, settings =E<gt> \@rows }>, with
  500: one row per key in C<@App::FileSync::Settings::SETTING_KEYS>.  Each row has the
  501: effective C<value>, a C<source> of C<default>, C<file>, C<env> or C<merged>, anda human-readable C<label> naming the file section, environment variable or
  502: built-in default that supplied it.  C<config_file> and C<config_dirs> may be
  503: passed, as for C<load>.
  504: 
  505: =head2 explain_repos
  506: 
  507:     my $repos = App::FileSync::Settings::explain_repos(%args);
  508: 
  509: Resolves C<ssh_identity>, C<ssh_known_hosts> and C<server_command> for every
  510: repo in a client config.  C<config> is the hashref from
  511: C<App::FileSync::Config::load_client>, C<report> is the result of C<explain>,
  512: and C<config_file> is the client config path used in labels.
  513: 
  514: Each entry has C<repo>, C<transport>, C<server> (when the repo records one) and
  515: C<ssh>: one C<{key, value, source, label}> row per setting, where C<source> is
  516: C<repo> (the repo's own entry), C<process> (the settings reported by C<explain>)
  517: or C<default> (ssh's own default, when nothing sets a value).  C<ssh> is
  518: C<undef> for the local transport, which never runs ssh.
